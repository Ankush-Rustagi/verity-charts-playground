# Verity DataViz Primitive Set

The stories in `01 Highcharts` and `02 visx` show **what production looks like today**. The stories here show **what the audit recommends for tomorrow**: one Story per proposed Verity DataViz primitive component, abstracted away from individual product team implementations.

Each primitive Story has the same shape:

- **Chart** on the left, rendered live with full Storybook Controls so you can play with every parameter.
- **Proposed Verity prop API** panel on the right, mapping raw Highcharts options to the opinionated structured props the primitive would expose.
- **Production sources this primitive covers** table showing which inventory surfaces and Verkada-Web file paths the primitive replaces.
- **Design notes** on tradeoffs and open questions for the Verity team.

This section is intentionally implemented as **annotated replicas, not committed React components**. The Controls bind directly to Highcharts options so the interactivity is real. The annotation panels show how those raw options would translate to a structured Verity prop surface. The goal is to drive the Verity team's component-spec conversation with a concrete artifact, not to ship the primitives prematurely.

## Why annotated replicas, not real components?

This was a deliberate choice. Three reasons:

1. **The spec is not settled.** The audit *recommends* an API; the Verity team has to *commit* to one. Shipping a real `<ColumnChart>` here would either bias that conversation toward a single API shape or ship a different API than what eventually lands in `packages/verity`.
2. **Live Controls beat static type definitions.** The most useful thing for a design review is "drag this slider and watch what happens." Real React components add a wrapper layer that doesn't change what you see, but does add a maintenance surface inside the playground.
3. **The annotation panel forces the abstraction conversation explicitly.** When you see `plotOptions.column.borderRadius: 4` next to `columnStyle: { rounded: true }` in the same row, it's obvious which decisions the Verity primitive needs to make.

When the team is ready to commit to a real API, the conversion is one-to-one: each annotation row becomes a typed prop in the component definition.

## What you can do here

- **Tweak props live.** Open any primitive Story, use the Controls panel at the bottom to change values, see the chart update.
- **Compare to production.** Open the same primitive's `01 Highcharts` peer story side by side (in two browser tabs) to see how the primitive abstracts the production options.
- **Generate the spec.** When you're ready to commit to an API, the "Proposed Verity prop API" tables across all 8 primitives are the spec draft.
